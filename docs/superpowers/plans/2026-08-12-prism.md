# Prism Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a working application that turns scattered client inputs (transcripts, WhatsApp, PDFs, screenshots, audio, websites) into an evidence-grounded business requirement, a better-process proposal, a solution blueprint, and a generated clickable POC.

**Architecture:** A staged pipeline (ingest → segment → extract → reconcile → synthesise → blueprint → POC) where every AI-produced claim cites addressable evidence units, and every stage is wrapped in a closed verification loop: free deterministic validators first, then an adversarially-prompted LLM critic, with failures fed back as the next instruction for up to 3 attempts before an explicit human-review flag. Next.js App Router holds both the UI and the API; SQLite persists engagements, sources, evidence, claims and the run trace.

**Tech Stack:** Next.js 15 (App Router), TypeScript (strict), Tailwind CSS v4, `better-sqlite3`, Zod, OpenAI SDK (`gpt-4.1` / `gpt-4.1-mini` / `whisper-1` / `text-embedding-3-small`), `unpdf`, `cheerio`, `mermaid`, `vitest`.

## Global Constraints

- **Node ≥ 20.** Verified toolchain: Node 22.22.0, npm 10.9.4.
- **TypeScript strict mode on.** No `any` in `src/lib/**` except at parsed-JSON boundaries, immediately narrowed by Zod.
- **Every LLM call goes through `src/lib/llm/index.ts`.** No direct `openai` import outside `src/lib/llm/`. This is what makes the run trace complete and the provider swappable.
- **Every LLM call uses a strict JSON Schema** and is re-validated in-process with Zod. `finish_reason === "length"` is thrown as an error, never returned as an answer.
- **Critic schemas emit `reasoning` before `verdict`.** Field order in a structured-output schema is load-bearing: a verdict token generated first makes the reasoning decorative.
- **No secrets committed.** `.env` is gitignored; `.env.example` is committed. A pre-computed demo run is committed so the app is fully explorable with no API key.
- **Offline test suite must pass with no `OPENAI_API_KEY` present.** Live tests are a separate command.
- **Accessibility:** WCAG AA contrast, visible focus states on all interactive elements, `prefers-reduced-motion` respected, no colour-only signalling.
- **Commit after every task.** Conventional commit prefixes (`feat:`, `test:`, `fix:`, `docs:`, `chore:`).
